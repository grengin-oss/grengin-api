# Grengin API 0.9.5

## Changes

- Security hardening for authorization, role/department transactions, audit
  persistence, file handling, chat edits and MCP OAuth.
- Organization/department chat sharing, frozen snapshots, private copies and
  eligible-user in-app notifications.
- Explicit AI-engine installation: startup no longer installs every catalog
  provider. Catalog-backed engines can be deleted without being recreated.
- The first API key enables an engine unless explicitly disabled. New engines
  get bounded model defaults; activation/rotation preserves restrictive policy.
- Concurrent installations cannot create duplicate rows; key rotation cannot
  overwrite a concurrent disable with a stale enabled flag.
- Image tags are derived from Cargo and cannot publish before the matching
  compatibility catalog and backend source commit are available.

## Deployment

Back up the database before the share migration. Its down migration deletes
shares and their notifications; it is not a lossless rollback. Existing AI-engine
rows are retained until deliberately deleted. SSE transport is unchanged.

## Known Issues

The preceding audit's dependency advisories remain; this release does not claim
to resolve them. Runtime catalog reloads still have an unversioned manifest path,
and public-bundle preparation does not fully validate the catalog schema. See
`docs/release-0.9.5-audit.md` for details. Optional copy indexing can be skipped at capacity,
and a process crash during file staging can leave orphaned bytes.

This release targets a single backend instance, not distributed/Redis operation.
