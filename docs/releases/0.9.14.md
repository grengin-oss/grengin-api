# 0.9.14 same-version hotfix candidate

This combines the reviewed 0.9.14 integration, PRs #107–#116 and #119–#123 where applicable, and the managed-provider review fixes. The 0.9.6/0.9.8 backport PRs and the old instance-connection PR are not part of this release.

## Changes

- Preserve edit replies across refreshes; add owner-only resumable streams with bounded replay memory and stalled-reader detachment. Existing polling remains available.
- Redact connector arguments/results from browser history and streams into short summaries. Full model input and administrator execution logs retain their existing behavior.
- Keep token/cost accounting monotonic across tool rounds, late cache counts, stopped/error replies and deleted conversations. Optional title/context publication failures preserve the user's chat.
- Recheck live MCP permissions, bound/cancel tool calls, validate credential destinations and headers, and retain checked SSO egress and first-login race protections.
- Expose localized model summaries, specialties, recommendations and catalog default hints; preserve attachment checks and bound image/CSV processing.
- Install Grengin for a verified first managed creator in the same transaction as the owner. It starts enabled with an empty allowlist and no selected defaults; repeated logins preserve administrator disable/deletion. Legacy confirmation retries are read-only and permanent denials terminate visibly.
- Route NVIDIA through Grengin 1.2. Gemini 1.10 adds thinking-token accounting for chat and image responses; only the new hotfix distribution may select it.

## Release ordering

1. Test the exact combined source and migration head, including PostgreSQL and catalog-contract tests.
2. Merge the tested API source. Main pushes validate code only; image publication requires a tag or explicit workflow dispatch.
3. Generate a candidate 0.9.14 distribution pinned to that final API SHA and the catalog-source SHA. Preserve every existing provider version/hash, adding the new compatible packages and choosing their new defaults only in 0.9.14.
4. Review the exact same-version catalog replacement, then publish the approved catalog and explicitly run image publication. Do not weaken the exact-revision compatibility gate to make a mismatched build pass.
5. Verify both image architectures, revision labels and migration head before any operator deployment. No VM, Hatchery or Cloudflare deployment is implied by merging this source.

The published 0.9.14 index currently pins an older API and Grengin/Gemini packages. It is not proof this hotfix is live. Existing immutable packages and older distributions remain unchanged. Standalone Grengin pairing and the identity tool are not implemented by this release. Existing dependency advisories and non-root container migration remain separate work.

For installations with automatic migrations disabled, apply the migrations through `m20261119_000002_grengin_engine_consent` before starting the new backend. The frontend should consume the connector `summary` contract; raw previews are no longer available. Remaining-budget badges require live budget logic and are not supplied by catalog price tiers.
