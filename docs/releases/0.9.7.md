# Grengin API 0.9.7 Staging Candidate

This candidate includes the connector OAuth broker integration from
feat/connector-oauth-broker. It is not a published release or image.

- User-owned connector APIs store encrypted connection grants, require explicit
  owner approval and expose connection state without returning credentials.
- MCP server/connection listings expose approved broker connections; tool traffic
  remains direct from the backend to the vendor.
- Deploy the companion grengin-service fix, commit
  fe72fcea3c0018c6ed2ce54c95b425d66491d7f5 on feat/connector-oauth-broker. It verifies
  bearer-shaped user tokens with Slack, rejects bot identities, classifies spent
  authorization codes as reconnect-required and logs only safe diagnostics.
- The backend migration head is m20261028_000001_create_connectors. Apply service
  migration 0018_connector_oauth_broker.sql to the selected staging D1 database.
- Release-mode discovery requires the reviewed 0.9.7 compatibility catalog pinned
  to the exact build commit. Do not reuse or overwrite the 0.9.6 distribution.

Real Slack consent, owner approval and direct MCP tool listing succeeded with
27 tools through a local webapp and a snapshot of the development database.
Model-led Slack tool execution remains unverified because replacement LLM keys
are needed. The temporary frontend callback override is not a production change.

See ../connector-oauth-staging.md and ../connector-oauth-broker-test-report.md for
configuration, the API contract, checks and remaining staging gates.
